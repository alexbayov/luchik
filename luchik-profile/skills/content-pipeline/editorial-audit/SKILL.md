# Post-audit пайплайн — проверка готового текста

Этот навык активируется **после** создания текста от лица «Лучи». Он прогоняет текст через все проверки редполитики и выдаёт отчёт с правками.

---

## Алгоритм аудита

### Шаг 1: Примени словарь замен (автоматически)

Прогони текст через детектор стоп-слов. Найди и отметь все вхождения из списков ниже.

**Негативные формулировки → нужно заменить:**
- «я не знаю», «невозможно», «вы не правы», «вы неправильно поняли», «это не наша вина», «читайте в договоре», «у нас проблемы», «вам необходимо предоставить», «подлежит урегулированию», «это сложно», «не знаю, поймёте ли», «успокойтесь», «это ерунда», «изучите в правилах», «ожидайте», «ознакомьтесь на сайте»

**Канцелярит → нужно заменить:**
- «в соответствии с», «осуществить», «пролонгация», «калькуляция», «имеет место быть», «информируем вас», «в рамках», «надлежащим образом», «вышеуказанный», «нижеподписавшийся», «настоящим уведомляем»

**Избыточная бренд-лексика → нужно удалить/сократить:**
- «лучистого», «сияем», «лучи добра», «озарим», «солнечные», «на крыльях света», «волшебный», «лучи богатства», «лучи здоровья»

**Запрещённые темы (красные флаги) → немедленно удалить:**
- Политика, военные конфликты, религия
- Шутки о здоровье, травмах, финансах
- Оценочные суждения, наставления

### Шаг 2: Проверь бренд-лексику

- Посчитай количество бренд-фраз: больше одной? → флаг 🟡
- Проверь контекст каждой: стресс/юридический/технический? → флаг 🔴 (убрать)
- Проверь склонение «Лучи»: есть «от Лучей», «с Лучами», «у Лучи»? → флаг 🔴 (переписать)

### Шаг 3: Проверь структуру

**Для писем:**
- Суть в первых двух строках?
- Разбито на короткие абзацы?
- Есть понятный следующий шаг?

**Для телефонных скриптов:**
- Идентификация в первые 10 секунд?
- Минимум 1 фраза с ценностями?
- Бренд-фраз 1–2, не больше?

**Для любых текстов:**
- Нет «воды»? Короткие фразы?
- Термины расшифрованы?
- Нет канцелярита?

### Шаг 4: Верификация ссылок 🔗

Если в тексте есть ссылки — проверь каждую:

- [ ] Ссылка открывается (HTTP 200, не 404/редирект на ошибку)
- [ ] Контент на странице соответствует тому, что заявлено в тексте
- [ ] Ссылка не ведёт на страницу-пустышку/заглушку/капчу
- [ ] Если ссылка не открылась — удали её из текста или замени на текстовую инструкцию для поиска

**Критическое правило:** Если не удалось проверить ссылку технически (маркетплейс блокирует ботов и т.п.) — не выдумывай её. Дай пользователю текстовую подсказку вместо ссылки.

**Инструмент:** `scripts/verify-links.py` — автоматическая проверка всех URL в тексте.
```bash
python3 ~/.hermes/skills/content-pipeline/editorial-audit/scripts/verify-links.py <файл>
python3 ~/.hermes/skills/content-pipeline/editorial-audit/scripts/verify-links.py --url "https://..."
python3 ~/.hermes/skills/content-pipeline/editorial-audit/scripts/verify-links.py --text "Текст со ссылками"
```

### Шаг 5a: Проверь сегментное соответствие

- B2B2C/Премиум: достаточно ли официально? не слишком ли «тепло»?
- B2C: достаточно ли доступно? не слишком ли сухо/формально?

### Шаг 5b: Финальный вердикт

Задай вопрос: **«Что почувствует клиент после прочтения?»**

Сверь с эталоном:
> «Меня поняли и слышат»  
> «Всё объяснили просто и ясно»  
> «Я знаю, что делать дальше»  
> «Мне помогают, я чувствую заботу»

## Шаг 6: Аудит презентаций (слайдов)

Этот шаг активируется, когда нужно проверить готовую презентацию (слайды, PDF, PPTX) на нарративную полноту, структуру, информационную плотность и эффективность призыва к действию.

Отличается от текстового аудита: здесь проверяется **визуальный нарратив и сквозная логика**, а не лексика отдельных фраз.

### Алгоритм аудита презентации

**1. Извлеки контент из презентации**

- Если PDF — конвертируй страницы в PNG (200 DPI, pymupdf `get_pixmap`)
- Если PPTX — используй python-pptx для извлечения текста со слайдов
- Если извлечение текста затруднено (графика, сканы) — используй pixel-level анализ:
  - Цветовые схемы (тёмные/светлые слайды → тип контента)
  - Плотность текста по зонам (слишком пусто / перегружено)
  - Наличие акцентных цветов (данные, CTA, разделители)

**2. Оцени нарративную структуру**

Пройди по слайдам и ответь на вопросы:

- [ ] Есть ли чёткая трёхактная структура: проблема → решение → действие?
- [ ] Переходы между секциями плавные или резкие? Нужен ли слайд-мостик?
- [ ] Каждый слайд делает одну работу или пытается сказать всё сразу?
- [ ] Есть ли социальное доказательство (кейсы, логотипы, цифры)? Если нет — флаг 🟡

**3. Оцени информационную плотность**

Для каждого слайда определи:

- **Пустой слайд** (< 5% текста/контента) — флаг 🟡 (недоиспользован)
- **Сбалансированный** (15–40% контента) — ✅
- **Перегруженный** (> 50% контента, 14+ текстовых блоков) — флаг 🔴 (нужно разбить на 2-3 слайда)

**4. Оцени призыв к действию (CTA)**

- [ ] CTA явный и заметный (не зарыт в dense-слайде)
- [ ] CTA подкреплён предшествующими слайдами (данные → доверие → предложение)
- [ ] Перед CTA есть контактный/Q&A слайд
- [ ] После CTA нет «обрыва» (последний слайд — это CTA или контакты)

**5. Проверь актуальность данных**

- [ ] Есть ли год/источник у каждой статистики?
- [ ] Данные не старше 2 лет (для 2026 года — данные 2024+)
- [ ] Если данные за 2023 и раньше — нужен апдейт или параллельная статистика

**6. Общая оценка**

Суммируй по категориям:

| Категория | Оценка | Комментарий |
|-----------|--------|-------------|
| Фрейминг проблемы | A/B/C/D | Достаточно ли контекста? |
| Роль спикера/HR | A/B/C/D | Понятна ли роль и действия? |
| Решение/продукт | A/B/C/D | Убедительно ли представлено? |
| Призыв к действию | A/B/C/D | Заметен, подкреплён, не зарыт? |
| Визуальный дизайн | A/B/C/D | Единая цветовая схема, не перегружено? |
| Нарративный поток | A/B/C/D | Логичные переходы, нет дыр? |

**Итоговая оценка:** X/100 (функционально / нужно доработать / требуется пересборка)

### Рекомендуемые типы недостающих слайдов

При аудите проверь наличие этих типов (добавь в рекомендации, если отсутствуют):

1. **Слайд-мост** — «Почему X, а не Y» (переход от проблемы к решению)
2. **Социальное доказательство** — логотипы клиентов, цитаты, кейсы
3. **Простой CTA** — отдельный слайд с крупным предложением, без лишней информации
4. **Контакты / Q&A** — перед финальным CTA, чтобы запрос не повис
5. **Ценовое предложение** — если есть в dense-слайде, вынести на отдельный слайд

### Инструмент

```bash
# Конвертация PDF в PNG для визуального анализа
python3 -c "
import pymupdf
doc = pymupdf.open('presentation.pdf')
for i, page in enumerate(doc):
    pix = page.get_pixmap(dpi=200)
    pix.save(f'slide_{i+1:02d}.png')
print(f'Сохранено {len(doc)} слайдов')
"
```

## Формат отчёта

```
📊 ОТЧЁТ АУДИТА

🔴 Критические (нужно исправить):
  • [конкретная фраза] → причина → замена

🟡 Рекомендации (стоит улучшить):
  • [конкретная фраза] → что не так → предложение

🟢 Пройдено:
  • То, что соответствует редполитике

📝 ИТОГОВАЯ ОЦЕНКА: [X]/10
   Общий вердикт: [готово к отправке / нужно доработать / требуется полная переработка]
```

## Быстрый аудит (3 вопроса)

Если нужно быстро — задай четыре вопроса:

1. **Есть ли красные флаги?** (канцелярит, негатив, запрещённые темы, бренд-перебор)
2. **Понятно ли с первого раза?** (суть в начале, коротко, без «воды»)
3. **Что почувствует клиент?** (поняли, помогли, позаботились?)
4. **Ссылки проверены?** (каждая открывается, ведёт куда надо, не выдумана)
